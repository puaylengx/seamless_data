Git Workflow

แนวทางการใช้ Git ในโปรเจกต์นี้ ครอบคลุม branch naming, เมื่อไหร่ควรสร้าง branch, ขั้นตอนทำงาน และเมื่อไหร่ควร merge

โครงสร้าง Branch หลัก

main production-ready เสมอ — ห้าม push ตรง
feature/db-connection
fix/ssh-tunnel-paramiko
docs/database-html
docs/knowledge shared branch — หลายคนใช้ร่วมกัน
⚠️
ห้าม push ตรงเข้า main — ทุกการเปลี่ยนแปลงต้องผ่าน branch และ merge เท่านั้น

Branch Naming

<type>/<short-description>
Typeใช้เมื่อตัวอย่าง
feature/เพิ่ม feature ใหม่feature/db-connection
fix/แก้ bugfix/ssh-tunnel-paramiko
docs/เพิ่ม/แก้ documentationdocs/database-html
chore/setup, config, toolingchore/gitignore-requirements
refactor/ปรับโครงสร้างโค้ด ไม่เปลี่ยน behaviorrefactor/connection-module
spike/ทดลอง/สำรวจ ยังไม่แน่ใจspike/bigquery-loader

เมื่อไหร่ควรสร้าง Branch ใหม่

สถานการณ์สร้าง branch ใหม่?
เพิ่ม feature ใหม่✅ เสมอ
แก้ bug✅ เสมอ
เพิ่ม/แก้ docs งานใหญ่หรือหลายคนทำพร้อมกัน✅ เสมอ
ทดลอง/spike✅ เสมอ
แก้ typo เล็กน้อยใน branch ที่กำลังทำอยู่⚠️ ไม่จำเป็น

ขั้นตอนทำงาน (คนเดียว)

  • 1
    อัปเดต main ให้ล่าสุดก่อนเสมอ 
    git checkout main
git pull origin main
  • 2
    สร้าง branch ใหม่จาก main 
    git checkout -b feature/db-connection
  • 3
    ทำงาน แล้ว commit บ่อยๆ ทีละน้อย 
    git add helpers/
git commit -m "feat(db): add SSH and direct connection module"

git add tests/
git commit -m "test(db): add connection test script"
  • 4
    Push branch ขึ้น remote 
    git push -u origin feature/db-connection
  • 5
    Merge กลับ main เมื่องานเสร็จ 
    git checkout main
git pull origin main          # อัปเดต main อีกครั้ง
git merge feature/db-connection
git push origin main
  • 6
    ลบ branch ที่ไม่ใช้แล้ว 
    git branch -d feature/db-connection           # ลบ local
git push origin --delete feature/db-connection  # ลบ remote

เมื่อไหร่ควร Merge

สถานการณ์Action
งานใน branch เสร็จ ทดสอบผ่านแล้วmerge เข้า main
branch ค้างนาน main มี commit ใหม่git merge main เข้า branch ตัวเองเพื่อ sync
หลายคนใช้ branch เดียวกันไม่ merge เข้า main จนกว่าทุกคนพร้อม

Commit Message — Conventional Commits

<type>(<scope>): <subject>

type เดียวกับ branch  |  scope คือส่วนที่แก้  |  subject กระชับ ไม่เกิน 72 ตัวอักษร

# ✅ ดี — บอก what และ why ชัดเจน
feat(db): add keepalive options to prevent idle connection drop
fix(ssh): pin paramiko <3.0 to fix DSSKey removal in paramiko 3.x
docs(db): move navbar from sidebar to top for better readability
chore: add .gitignore and requirements.txt

# ❌ ไม่ดี — กว้างเกินไป ไม่รู้ว่าแก้อะไร
update files
fix bug
add stuff
