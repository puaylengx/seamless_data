Shared Branch

แนวทางการทำงานเมื่อหลายคนใช้ branch เดียวกัน โดยเฉพาะกรณี docs/knowledge ที่หลายคน update ไฟล์ *.html พร้อมกัน

สถานการณ์

คน A

docs/knowledge/database.html

คน B

docs/knowledge/finance.html

คน C

docs/knowledge/research.html

ทุกคนทำงานบน branch docs/knowledge เดียวกัน แต่รับผิดชอบคนละไฟล์ — วิธีนี้ลดโอกาสเกิด conflict ได้มากที่สุด

💡
หลักการ: แบ่งงานให้แต่ละคนรับผิดชอบ คนละไฟล์ — ถ้าไม่ได้จริงๆ ค่อย resolve conflict ตามขั้นตอนด้านล่าง

ขั้นตอน "Pull before Push" — ทำทุกครั้งก่อนเริ่มงาน

  • 1
    Switch ไป branch และ pull งานล่าสุด 
    git checkout docs/knowledge
git pull origin docs/knowledge
  • 2
    แก้ไฟล์ของตัวเอง 
    # แก้ไฟล์ที่ตัวเองรับผิดชอบ เช่น database.html
  • 3
    Commit และ push 
    git add docs/knowledge/database.html
git commit -m "docs(db): update navbar to top layout"
git push origin docs/knowledge

เมื่อเกิด Conflict

เกิดขึ้นเมื่อ 2 คนแก้ ไฟล์เดียวกัน บรรทัดเดียวกัน แล้ว push ต่างเวลากัน

1. Pull แล้วพบ conflict

git pull origin docs/knowledge
# ขึ้น: CONFLICT (content): Merge conflict in docs/knowledge/database.html

2. เปิดไฟล์ที่ conflict — จะเห็น marker แบบนี้

<<<<<<< HEAD(งานของเรา) <nav class="navbar"> ======= <nav class="sidebar"> >>>>>>> origin/docs/knowledge(งานของคนอื่น)

3. แก้ไขให้เหลือแบบที่ถูกต้อง แล้ว commit

# ลบ marker ออก เหลือเฉพาะโค้ดที่ต้องการ
git add docs/knowledge/database.html
git commit -m "docs: resolve conflict in database.html navbar"
git push origin docs/knowledge
⚠️
ห้าม commit ไฟล์ที่ยังมี <<<<<<< หรือ >>>>>>> อยู่ — ต้องแก้ให้หมดก่อนเสมอ

Merge เข้า main เมื่อทุกคนพร้อม

git checkout main
git pull origin main
git merge docs/knowledge
git push origin main

# ลบ branch หลัง merge (ถ้าไม่ใช้แล้ว)
git branch -d docs/knowledge
git push origin --delete docs/knowledge

Tips ลด Conflict

วิธีรายละเอียด
แบ่งไฟล์คนละส่วนแต่ละคนรับผิดชอบคนละไฟล์ — conflict จะไม่เกิดเลย
pull ก่อนเริ่มทำงานทุกครั้งลดระยะห่างระหว่าง local กับ remote
commit ทีละน้อย push บ่อยๆconflict มีขอบเขตเล็ก แก้ง่ายกว่า
สื่อสารในทีมแจ้งเพื่อนก่อนแก้ไฟล์ที่ใช้ร่วมกัน
